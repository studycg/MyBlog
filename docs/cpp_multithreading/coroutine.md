# 协程

## 背景

传统的普通函数只有一个入口和一个出口：调用时开始执行，`return` 时结束并销毁所有局部变量。

**协程**则是可以**挂起和恢复**的函数。

- 当协程挂起时，它的状态（局部变量、执行进度）会被保存在堆（Heap）上。
- 当协程恢复时，它会从上次挂起的地方继续执行。

只要一个函数包含了 `co_await`、`co_yield` 或 `co_return` 中的任意一个关键字，编译器就会自动将它变成一个协程。

## 三大关键字

**`co_await`**：挂起当前协程，直到等待的异步操作完成。常用于网络请求、文件 I/O 或定时器。

**`co_yield`**：挂起协程并向调用者返回一个值。常用于实现生成器（Generator），产生一个数据流。

**`co_return`**：结束协程并返回最终结果（或者返回 `void`）。协程内部不能使用普通的 `return`。

**`co_await <表达式>`**：

- **语义**：暂停当前协程，等待某个异步任务完成。

**`co_yield <表达式>`**：

- **语义**：暂停当前协程，并向调用者返回一个值。

**`co_return <表达式>`**：

- **语义**：协程运行结束，并返回最终结果。注意，协程里不能使用 `return`。

## 三大核心组件

#### A. Promise 对象 (`promise_type`)

这是协程的**内部控制器**。它定义了协程启动时要做什么、挂起时要做什么、返回值时如何处理，以及发生异常时怎么办。

- 开发者必须在自定义的返回类型中嵌套一个 `promise_type` 结构体。

#### B. 协程句柄 (`std::coroutine_handle`)

这是协程的**外部遥控器**。调用者通过它来控制协程的生命周期。

- **`.resume()`**：恢复协程的执行。
- **`.destroy()`**：销毁协程状态，释放内存。
- **`.done()`**：检查协程是否已经执行完毕。

#### C. 等待体 (Awaiter)

它决定了 `co_await` 发生时的具体行为。一个合法的 Awaiter 必须实现三个方法：

- `await_ready()`：检查结果是否已经准备好（如果准备好了就不必挂起）。
- `await_suspend()`：协程挂起后执行的逻辑（常用于将协程句柄注册到事件循环或回调函数中）。
- `await_resume()`：协程恢复后，`co_await` 表达式的返回值。
