# 列表初始化

使用列表初始化时，**可添加等号，也可以不添加。**

```c++
C++
// 1. 基础变量
int a{10}; 

// 2. 数组
int arr[]{1, 2, 3}; 

// 3. 容器 (STL)
std::vector<int> vec{1, 2, 3, 4};
std::map<int, string> dict{{1, "Alpha"}, {2, "Beta"}};

// 4. 动态分配内存
int* p = new int[3]{10, 20, 30};

// 5. 对象
Point3D p1{1.2, 3.4, 5.6};
```

```c++
struct Point
{
	int _x;
	int _y;
};
int main()
{
	//使用大括号对内置类型进行初始化
	int x1 = { 1 }; //可添加等号
	int x2{ 2 };    //可不添加等号

	//使用大括号对数组元素进行初始化
	int array1[]{1, 2, 3, 4, 5}; //可不添加等号
	int array2[5]{0};            //可不添加等号

	//使用大括号对结构体元素进行初始化
	Point p{ 1, 2 }; //可不添加等号

	//C++11中列表初始化也可以用于new表达式中（C++98无法初始化）
	int* p1 = new int[4]{0};//不可添加等号
	int* p2 = new int[4]{1,2,3,4};//不可添加等号
	return 0;
}
```

用大括号对new表达式初始化时不能加等号

```c++
// 错误写法：new表达式后加=，违反语法规则
int* p = new int[4] = {1,2,3,4}; 
```

## 防止类型变窄

如果你尝试将一个高精度的值赋给低精度的变量，使用 `{}` 会直接导致**编译错误**，而传统方式只会给你一个警告（甚至没有警告），然后悄悄丢失精度。

```c++
double pi = 3.1415926;

int x = pi;     // 传统方式：允许，x 变成 3 (隐式转换)
int y(pi);     // 传统方式：允许，y 变成 3

int z{pi};     // C++11 列表初始化：编译报错！强制要求精度匹配
```

```c++
struct Timer {};

// 你以为在创建一个对象，其实编译器认为你在声明一个
// 返回值为 Timer，不接受参数的函数
Timer t(); 

// 使用 C++11 大括号，彻底消除歧义
Timer t1{}; // 明确这是一个对象初始化
```

为什么C++11可以用列表初始化呢？因为引入了**initializer_list**

## initializer_list

initializer_list没有提供对应的增删改查接口，只有size()begin()end()。

initializer_list并不是专门用于存储数据的，而是为了让其他容器支持列表初始化的。

C++11后这些容器之所以支持使用列表进行初始化，根本原因是因为C++11给这些容器都增加了一个构造函数，这个构造函数就是以initializer_list作为参数的。

```c++
class Polyline {
public:
    Polyline(std::initializer_list<Point3D> points) {
        for (auto p : points) {
            // 将点加入内部存储
        }
    }
};

// 使用
Polyline line{{0,0,0}, {1,1,1}, {2,2,2}};
```

- 最好也增加一个以initializer_list作为参数的赋值运算符重载函数，以支持直接用列表对容器对象进行赋值，但实际也可以不增加。

如果没有增加以initializer_list作为参数的赋值运算符重载函数，下面的代码也可以正常执行：

```
vector<int> v = { 1, 2, 3, 4, 5 };
v = { 5, 4, 3, 2, 1 };
```

- 对于第一行代码，就是调用以initializer_list作为参数的构造函数完成对象的初始化。
- 而对于第二行代码，会先调用initializer_list作为参数的构造函数构造出一个vector对象，然后再调用vector原有的赋值运算符重载函数完成两个vector对象之间的赋值。

# auto和decltype

## auto

`auto` 的核心逻辑是：**编译器通过变量的初始值，推导出变量的类型。**

```c++
// 1. 简化冗长的迭代器
std::vector<Point3D> points;
// 以前：std::vector<Point3D>::iterator it = points.begin();
auto it = points.begin(); 

// 2. 配合范围 for 循环 (Range-based for loop)
for (const auto& p : points) {
    //const auto& 保证了性能和只读安全
}

// 3. 接收 Lambda 表达式
auto intersect_func = [](const Ray& r, const Surface& s) { /* ... */ };
```

**必须初始化**：`auto x;` 是不合法的，因为编译器没法“盲猜”。

**会丢失 `const` 和引用**：

```c++
int i = 0;
int& ref = i;
auto a = ref; // a 的类型是 int，而不是 int&（引用被剥离）

const int ci = 0;
auto b = ci;  // b 的类型是 int，而不是 const int（顶层 const 被剥离）
```

如果你想要引用或 const，需要手动加上：`const auto& c = ci;`

## decltype

 `decltype`（declared type）就是“**给我一个表达式，我告诉你它是什么类型**”，但它并不会真正运行那个表达式。

```c++
int x = 0;
decltype(x) y = 10; // y 的类型就是 int

std::vector<int> vec;
decltype(vec.begin()) it; // 定义一个和 vec 迭代器同类型的变量，无需初始化
```

通过`typeid(变量名).name()`的方式可以获取一个变量的类型，但无法用获取到的这个类型去定义变量。

decltype推导表达式类型：

```c++
int i = 10;
decltype(i) a = i;   // (1) a 是什么类型？
decltype((i)) b = i; // (2) b 是什么类型？（注意双括号）
```

 `decltype((i))` 这一对**双括号**其实触发了 C++ 里的一个特殊规则：

- **`decltype(i)`**：对应的是“变量名”，所以它直接返回该变量定义的类型，即 `int`。

- **`decltype((i))`**：括号让 `(i)` 变成了一个**表达式**。在 C++ 中，如果一个表达式可以放在赋值号左边（左值），`decltype` 就会推导出该类型的**引用**。

  **结论**：`b` 的类型是 **`int&`**（即 `i` 的引用）。

**auto与decltype结合实现返回类型后置**

```c++
// 以前我们很难写出 add 的返回值类型，因为 T1+T2 可能是 int，也可能是 double
template <typename T1, typename T2>
auto add(T1 x, T2 y) -> decltype(x + y) {
    return x + y;
}

auto result = add(1, 2.5); // result 自动推导为 double
```

> decltype什么时候返回值？什么时候返回引用？

**单纯的变量名**：如 `decltype(i)`。

- **结果**：该变量声明时的原始类型。

**表达式**：如 `decltype((i))`、`decltype(a + b)`、`decltype(arr[0])`。

- 如果表达式是**左值**（可以取地址，如括号里的变量、解引用、返回引用的函数），结果是 **引用 `T&`**。
- 如果表达式是**纯右值**（临时值，如 `a + b`、返回值的函数），结果是 **值 `T`**。

下面的情况都不返回引用

**A. 指针成员访问**

```c++
struct Node { int val; };
Node* ptr = new Node{10};
decltype(ptr->val) a; // int，因为它是变量名
```

**B. 函数返回“值”**

```c++
int get_val() { return 10; }
decltype((get_val())) x; // int，因为 get_val() 是右值表达式
```

在刚刚返回类型后置的例子中：

x+y的结果，即加法运算符的结果是一个纯右值，所以返回的不是引用。

### decltype深入

✅ 规则1：如果 expr 是一个“未加括号的变量名”

```c++
int a = 10;
decltype(a)  // int
//decltype(a) == 变量的声明类型
```

✅ 规则2：如果 expr 是一个左值表达式

```c++
int a = 10;
decltype((a))  // 注意双括号
//decltype(expr) == T&
```

✅ 规则3：如果 expr 是右值表达式

```c++
decltype(expr) == T
```

举一些例子：

```c++
int& foo();
decltype(foo())  // int&
//foo() 返回的是 int& 表达式本身是左值表达式
    
int foo();     // 返回值
int& bar();    // 返回引用
decltype(foo())  // int
decltype(bar())  // int&
```

```c++
struct A {
    int value;
};

A& operator+(A&, A&);
decltype(x + y)	// A&
    
int a = 1;
int b = 2;
a + b;
decltype(a + b)  // int
```

| 返回类型 | 表达式类别 |
| -------- | ---------- |
| T        | prvalue    |
| T&       | lvalue     |
| T&&      | xvalue     |

# nullptr

在 C++11 之前，我们通常用 `NULL` 或 `0` 来表示空指针。但这会带来一个经典的**重载歧义**问题：

```c++
void func(int n) { std::cout << "调用 int 版"; }
void func(char* p) { std::cout << "调用指针版"; }

// 痛点
func(NULL); // 可能会调用 int 版！因为 NULL 往往被宏定义为 0
```

`nullptr` 是一种特殊的字面量，它的类型是 `std::nullptr_t`。它**只能**被转换成指针类型，不能转换成整数。

**安全性**：`func(nullptr)` 会明确调用指针版本的函数。

同时增加了可读性： `if (ptr == nullptr)` 比 `if (ptr == 0)` 语义更清晰。

> 为什么nullptr只能转换为指针？

`nullptr` 并不是一个预处理器宏，它是一个**编译器内置的关键字**，其类型是 `std::nullptr_t`。

这是通过 **模板转换运算符** 实现的。

- **智能匹配**：当你写 `int* p = nullptr;` 时，编译器会调用 `nullptr_t` 内部的 `operator T*()`，将 `T` 推导为 `int`。
- **类型安全**：`nullptr_t` **没有**定义到 `int` 或 `long` 的转换运算符。因此，如果你尝试 `int x = nullptr;`，编译器在 `nullptr_t` 类中找不到对应的 `operator int()`，就会直接报错。
- **布尔特例**：为了方便写 `if (ptr)`，`nullptr` 被允许隐式转换为 `bool`（结果始终为 `false`）。

```c++
class nullptr_t {
public:
    // 1. 它可以转换为任何类型的指针
    template<class T>
    constexpr operator T*() const { return 0; }

    // 2. 它可以转换为任何类成员指针
    template<class C, class T>
    constexpr operator T C::*() const { return 0; }

private:
    // 3. 严格禁止转换为整数（除了 bool）
    void operator&() const = delete;  // 禁止取地址
};
```

`nullptr` 在内存层面对应的数值依然是 `0x00000000`。

**它的魔力在于“编译期”的身份隔离：**

- **数值上**：它等于 0。
- **类型上**：它是一个强类型的对象，而不是字面量 0。

## 深入解析nullptr模板

一个类似于运算符重载的例子

```c++
operator 类型()
```

表示：把当前对象转换为某种类型

例如：`operator int()`表示可以转换为int

**对于第一个template**

```c++
template<class T>
constexpr operator T*() const { return 0; }
```

```c++
template<class T>
operator T*()
```

`operator T*()`的意思是：这个对象可以转换成任何类型的指针。

如果需要 `int*`、编译器就令 `T = int`、那么生成的函数就是：

```c++
operator int*()
```

如果需要`double*`、编译器就令`T = double`、那么生成的函数就是

```c++
operator double*()
```

```c++
nullptr_t np;
int* p = np;
```

编译器看到`int* p = np`后：需要把 `np` 转成 `int*`。

而类里有`operator T*()`：于是自动推导T=int

为什么返回0是合法的？

因为`0`可以隐式的转换为任何指针类型，数学上可以理解为0 → 空地址。

**对于第二个template**

```c++
template<class C, class T>
constexpr operator T C::*() const { return 0; }
```

这是成员指针的写法，例如：

```c++
struct A {
    int x;
};
```

变量x的类型是`int A::*`：含义是 指向 A 类中的 int 成员的指针

```c++
int A::* ptr = nullptr;
```

这里`T=int`、`C=A`

模板的含义：这个对象可以转换为任意类 C 的任意成员类型 T 的成员指针。

至此nullptr可以转换为：

- 任意普通指针（第一个模板）
- 任意成员指针（第二个模板）

```c++
目标类型  x = np;
```

译器做的事是：

1. 看看目标类型是什么
2. 去找能转换到这个类型的 operator
3. 用模板推导出 T

**为什么要delete operator&**

```c++
void operator&() const = delete;
```

为了禁止`&np` 因为真正的nullptr是一个特殊的字面值

这个模板只是粗略模拟，真实的nullptr更复杂。

- 不提供整数转换

- 只提供 bool 转换（有时）

- 利用语言规则限制

```c++
nullptr_t
   ↓
可转换为 T*
   ↓
可转换为 T C::*
   ↓
但不能变成整数
```

但实际上C++的nullptr禁止转换成整数等不是由于`operator int() = delete`来完成的，而是更深入的语言规则限制。它是语言级别内建类型，转换规则在编译器内部写死。

# 范围for循环

范围for循环是对使用begin()和end()的语法糖

所以如果自定义类实现了begin()和end()函数，就能直接支持范围for循环。

```c++
std::vector<double> knots = {0.0, 0.0, 0.5, 1.0, 1.0};

for (auto k : knots) {
    // 拷贝遍历：修改 k 不会影响原容器
}

for (auto& k : knots) {
    // 引用遍历：可以修改原容器里的值
    k += 0.1;
}

for (const auto& k : knots) {
    // 常量引用遍历：最推荐的做法！高性能且只读安全
}
```

# STL新增

> array、forward_list、unordered_map、unordered_set

array容器本质就是一个静态数组，即固定大小的数组。

array容器有两个模板参数，第一个模板参数代表的是存储的类型，第二个模板参数是一个非类型模板参数，代表的是数组中可存储元素的个数。比如：

```c++
int main()
{
	array<int, 10> a1;   //定义一个可存储10个int类型元素的array容器
	array<double, 5> a2; //定义一个可存储5个double类型元素的array容器
	return 0;
}
```

rray容器与普通数组对比：

- array容器与普通数组一样，支持通过[]访问指定下标的元素，也支持使用范围for遍历数组元素，并且创建后数组的大小也不可改变。
- array容器与普通数组不同之处就是，array容器用一个类对数组进行了封装，并且在访问array容器中的元素时会进行越界检查。用[]访问元素时采用断言检查，调用at成员函数访问元素时采用抛异常检查。
- 而对于普通数组来说，一般只有对数组进行写操作时才会检查越界，如果只是越界进行读操作可能并不会报错。
- 但array容器与其他容器不同的是，array容器的对象是创建在栈上的，因此array容器不适合定义太大的数组。

> forward_list

forward_list容器本质就是一个单链表。

forward_list很少使用，原因如下：

- forward_list只支持头插头删，不支持尾插尾删，因为单链表在进行尾插尾删时需要先找尾，时间复杂度为O(N)。
- forward_list提供的插入函数叫做insert_after，也就是在指定元素的后面插入一个元素，而不像其他容器是在指定元素的前面插入一个元素，因为单链表如果要在指定元素的前面插入元素，还要遍历链表找到该元素的前一个元素，时间复杂度为O(N)。
- forward_list提供的删除函数叫做erase_after，也就是删除指定元素后面的一个元素，因为单链表如果要删除指定元素，还需要还要遍历链表找到指定元素的前一个元素，时间复杂度为O(N)。

因此一般情况下要用链表我们还是选择使用list容器。

> unordered_map和unordered_set

关于这个看STL解析那几章。

C++11为每个容器增加了新方法：

- 提供了一个以initializer_list作为参数的构造函数，用于支持列表初始化。
- 提供了cbegin和cend方法，用于返回const迭代器。
- 提供了emplace系列方法，并在容器原有插入方法的基础上重载了一个右值引用版本的插入函数，用于提高向容器中插入元素的效率。
