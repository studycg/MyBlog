> 如果输入两个int，不使用if和switch等语句，如何判断哪个更大？

**使用绝对值**

$max(a,b)=\frac{a+b+∣a−b∣}{2}$

```c++
int max(int a, int b) {
    return (a + b + abs(a - b)) / 2;
}
```

**使用位运算**

$k=(a-b)>>31$

当a大于b时，$a−b≥0 \rightarrow k=0$

当a小于b时，$a−b<0 \rightarrow k=−1 (全1)$

```c++
int max(int a, int b) {
    int k = (a - b) >> 31;
    return a - k * (a - b);
}
//k=0
return a - 0 * (a - b) = a;
//k=-1
return a - (-1)*(a - b) = a + (a - b) = b;
```

# 柠檬微趣一面

## 源码 反码 补码

**原码**：

最高位（最左边的一位）代表符号位，**0 代表正数，1 代表负数**。其余位代表数值。

- $+5 \rightarrow [0000 0101]$
- $-5 \rightarrow [1000 0101]$

**反码**：

- **正数**：反码与原码相同。
- **负数**：符号位不变，其余各位取反（0变1，1变0）。

- $+5 \rightarrow [0000 0101]$
- $-5 \rightarrow [1111 1010]$

**补码**：

- **正数**：补码与原码相同。
- **负数**：在反码的基础上 **加 1**。

- $+5 \rightarrow [0000 0101]$
- $-5 \rightarrow [1111 1011]$

补码的作用：

**统一加减运算**

早期的计算机如果想做减法，需要设计一套专门的减法电路。

但如果使用补码，**减去一个数就等于加上它的补码**。

**数学原理**：补码类似于时钟的“模”运算。比如现在是 10 点，你想调回 6 点，你可以逆时钟拨 4 小时，也可以顺时钟拨 8 小时（$10 + 8 = 18$，在 12 小时制里就是 6 点）。

$$5 - 3 = 5 + (-3)$$

在补码中：

$5$ 的补码：`0000 0101`

$-3$ 的补码：`1111 1101`

相加结果：`1 0000 0010`（最高位溢出丢弃，剩下 `0000 0010`，即 $2$）

**解决零的歧义**

在**原码**中，零会有两种表现形式：

- $+0 \rightarrow 0000 0000$
- $-0 \rightarrow 1000 0000$

这在程序逻辑里非常麻烦（需要写两套判断语句）。而在**补码**中，$-0$ 的反码加 1 后会产生进位并溢出，最终结果依然是 `0000 0000`。

**补码保证了“零”的唯一性**，并且还额外多出了一个最小负数的表示空间（例如 8 位补码可以表示 $-128$ 到 $127$）。

| **类型** | **正数表示** | **负数表示**           | **零的表示**   |
| -------- | ------------ | ---------------------- | -------------- |
| **原码** | 符号位0+数值 | 符号位1+数值           | 两种（$\pm0$） |
| **反码** | 同原码       | 符号位不变，数值位取反 | 两种（$\pm0$） |
| **补码** | 同原码       | **反码 + 1**           | **唯一**       |

## 为什么补码负数多一个

我们以 4位二进制为例，总共有 $2^4 = 16$ 个可能的编码组合（从 `0000` 到 `1111`）。

在**原码**中：

- `0000` 表示 $+0$
- `1000` 表示 $-0$
- 结果：零占用了两个编码，导致正数和负数是对称的（都是 $1 \sim 7$），总共只能表示 15 个数（因为 0 重复了）。

在**补码**中：

- `0000` 唯一表示 $0$。
- 当我们按照“反码+1”的规则处理负数时，原码中的 `-0`（`1000`）经过变换后会变成什么呢？
  - `-1` 的补码是 `1111`
  - `-7` 的补码是 `1001`
  - 那么 **`1000`** 这个编码就空出来了，它可以被用来表示一个新的负数：**$-8$**。

## 算术移位与逻辑移位

**逻辑移位**

逻辑移位不考虑数字的“正负”，它把二进制序列看作纯粹的**位向量**。

- **逻辑左移**
  - 所有位向左移动，高位溢出丢弃。
  - **低位补 0**。
- **逻辑右移**
  - 所有位向右移动，低位溢出丢弃。
  - **高位补 0**。

**特点**：简单粗暴。逻辑右移通常用于处理 **无符号整数**，因为它不保留符号。

**算术移位**

算术移位专门为**带符号整数/即补码表示**设计，目的是在移位的同时保持数值的数学意义（正负号不变）。

- **算术左移**：
  - **通常等同于逻辑左移**
  - 补码中，左移一位等同于乘以 2，只要不发生符号改变导致的溢出。
  - 低位补 0。
- **算术右移**：
  - 所有位向右移动，低位溢出丢弃。
  - **高位补符号位**
    - 如果原来是 0（正数），高位就补 0；
    - 如果原来是 1（负数），高位就补 1。

- **左移 $n$ 位** $\approx$ 乘以 $2^n$

  **右移 $n$ 位** $\approx$ 除以 $2^n$

根据IEEE754

```c++

   1bit     8bit     23bit
```

## 空间中有1000个球 如何判断碰撞

要做的就是避免$O(n^2)$的两两对比

均匀网格/空间哈希/八叉树

**空间哈希：将连续空间离散化，用哈希表管理这些空间块**

如果真的开一个3维数组的话会直接爆内存

用空间哈希只存有物体的格子

```c++
struct Vec3 {
    float x, y, z;
};

struct Sphere {
    Vec3 pos;
    float r;
};

unordered_map<int, vector<int>> grid;

int hash(int x, int y, int z) {
    return x * 73856093 ^ y * 19349663 ^ z * 83492791;
}

void insert(vector<Sphere>& spheres, float h) {
    grid.clear();
    for (int i = 0; i < spheres.size(); i++) {
        int gx = floor(spheres[i].pos.x / h);
        int gy = floor(spheres[i].pos.y / h);
        int gz = floor(spheres[i].pos.z / h);
        int key = hash(gx, gy, gz);
        grid[key].push_back(i);
    }
}
```

每个格子如果有k个球，那么时间复杂度变为$O(n·k)$

## Monobehaviour的生命周期

```c++
Awake
→ OnEnable
→ Start
→ Update
→ LateUpdate
→ OnDisable
→ OnDestroy
```

**Awake**：脚本实例被加载时立即调用。即使脚本组件未激活（Disabled），只要物体是激活的，`Awake` 就会执行。适合初始化引用的赋值。

**OnEnable**: 在脚本被激活或物体被激活时调用。每次物体从隐藏变为显示时，都会触发。

**Start**: 在第一帧更新之前调用。只有在脚本组件被勾选激活的情况下才会执行。适合执行需要等待其他脚本 `Awake` 完成后的逻辑。



**FixedUpdate**: 以固定的时间间隔调用（默认 0.02s），不受帧率波动影响。**所有物理计算和位移逻辑都应放在这里。**

**OnTrigger/OnCollision**: 在物理引擎计算完成后，处理触发器或碰撞的回调。



**Update**: 每帧调用一次。由于帧率不稳定（比如 30fps 或 60fps），处理位移时通常需要乘上 `Time.deltaTime`。

**LateUpdate**: 在所有 `Update` 执行完后调用。常用于**摄像机跟随**，以确保角色已经移动完毕后再调整相机位置。



**OnDisable**: 脚本被禁用或物体被隐藏时调用。

**OnDestroy**: 脚本实例被销毁（如调用 `Destroy()`）时调用。

**OnApplicationQuit**: 玩家退出程序时在所有对象上调用。

| **阶段**   | **函数名**    | **触发频率** | **典型用途**          |
| ---------- | ------------- | ------------ | --------------------- |
| **初始化** | `Awake`       | 一次         | `GetComponent` 赋值   |
| **状态**   | `OnEnable`    | 多次         | 注册事件监听          |
| **物理**   | `FixedUpdate` | 固定频率     | 物理受力 (`AddForce`) |
| **逻辑**   | `Update`      | 每帧         | 玩家按键输入          |
| **后续**   | `LateUpdate`  | 每帧         | 摄像机平滑跟随        |
| **销毁**   | `OnDestroy`   | 一次         | 释放资源、清理引用    |
