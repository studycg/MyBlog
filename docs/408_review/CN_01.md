# UDP协议

## UDP 的特点

你可以用“**写信**”来类比 UDP，而 TCP 则是“**打电话**”。

- **无连接**：发送数据前不需要建立连接，减少了开销和延迟。
- **尽力而为（不可靠）**：不保证交付，不保证顺序，没有重传机制。
- **面向报文**：UDP 对应用层交下来的报文，既不合并，也不拆分，而是保留这些报文的边界。
- **无拥塞控制**：网络出现拥塞不会降低源主机的发送速率（这对实时游戏很重要，宁可丢包也不要自动降速导致的堆积）。
- **支持一对多/多对多**：支持广播和多播（局域网联机游戏常用）。

## UDP为什么无连接？

| **字段**       | **长度** | **作用**                                  |
| -------------- | -------- | ----------------------------------------- |
| **源端口号**   | 2 字节   | 发送方的端口，不需要回复时可全 0          |
| **目的端口号** | 2 字节   | 接收方的端口，决定数据交给哪个应用进程    |
| **长度**       | 2 字节   | UDP 报文单位（首部 + 数据）的总字节数     |
| **校验和**     | 2 字节   | 检测 UDP 报文在传输中是否有错，有错就丢弃 |

在 TCP 中，头部有复杂的 **标志位（SYN, ACK, FIN 等）** 和 **窗口大小**，用于维护连接状态。而 UDP：

- **没有状态字段：** 头部里根本没有地方记录“当前连接到哪一步了”。
- **不握手：** 发送方拿到数据，填上目的端口，直接就甩到网络上。它不关心接收方是否在线，也不需要接收方确认。
- **独立性：** 每一个 UDP 报文都是完全独立的，报文之间没有上下文关系。

## 为什么UDP不可靠？

**可靠—— TCP**

协议承诺：只要连接没断，我发出的数据，对方**一定能收到**，且**顺序正确**、**内容无误**、**不重复**。

**不可靠—— UDP**

协议承诺：我只负责把数据包传给网络，**尽力而为**，至于能不能到、什么时候到、是不是按顺序到，我**一概不管**。

### ① 没有确认和重传机制

- **对比：** TCP 头部有“序列号”和“确认号”。
- **UDP：** 头部只有端口和长度。如果数据包在路由器中因为拥塞被丢弃，UDP 头部没有任何字段能支持发送方知道“包丢了”，也没有任何机制去要求重发。

### ② 没有流量控制和拥塞控制

- **对比：** TCP 头部有“窗口大小”，会根据网络情况慢启动、拥塞避免。
- **UDP：** 哪怕网络已经堵死了，UDP 依然会按照应用层要求的速度拼命往外发。这种“只管发，不管到没到”就是不可靠的体现。

### ③ 仅有的保护：校验和

- UDP 唯一体现“可靠性”的地方就是**校验和**。
- 如果接收方计算校验和发现数据坏了，UDP 的处理逻辑非常果断：**直接丢弃**。它不会尝试修复，也不会告诉发送方重传。
