# 文件管理

## 结构

在类 Unix 系统（如 Linux, Android, iOS）中，这是一个核心哲学：无论是硬盘上的图片、键盘、鼠标，还是网络 Socket，都被抽象为**文件**。

**文件系统的两大部分：**

- **元数据（Inode）**：文件的“身份证”，存放在 **Inode Table** 中。
- **实际数据（Data Block）**：文件真正的内容，存放在 **Data Blocks** 中。

## Inode

**Inode（Index Node）** 是文件系统管理文件的核心。

Inode 是文件的索引节点，包含了文件的权限、大小和指向数据块的指针。

**一个 Inode 包含什么？**

- 文件权限（rwx）、所有者（UID/GID）。
- 文件大小、创建/修改时间。
- **关键：指向磁盘数据块的指针**。

**注意：Inode 里不存储文件名！** 文件名存放在**目录**里。目录本质上也是一个文件，它的内容是一张表：`文件名 <-> Inode 号`。

## 硬链接和软链接

| **特性**       | **硬链接 (Hard Link)**             | **软链接 (Symbolic/Soft Link)**            |
| -------------- | ---------------------------------- | ------------------------------------------ |
| **本质**       | 给 Inode 起了一个**别名**。        | 一个**独立的文件**，内容是目标文件的路径。 |
| **Inode 号**   | 和源文件共享同一个 Inode 号。      | 拥有自己独立的 Inode 号。                  |
| **跨分区**     | **不能**跨文件系统分区。           | **可以**跨分区，甚至指向不存在的文件。     |
| **删除源文件** | 文件依然存在，直到链接数为 0。     | 链接失效，变成“死链接”。                   |
| **对目录**     | 现代系统通常不允许对目录建硬链接。 | 可以对目录建软链接。                       |

## 虚拟文件系统VFS

由于世界上有各种格式的文件系统（NTFS, FAT32, ext4），操作系统为了让程序员用同一套代码（`read`/`write`）操作它们，加了一个中间层——**VFS**。

**VFS 的作用：** 定义了一套标准的函数接口。无论底层是硬盘还是 U 盘，程序员调用的接口都是统一的。这体现了 OS 极其重要的**抽象**思想。

# I/O模型

## 一次I/O的两个阶段

当你的程序调用 `read()` 去读取网络数据或磁盘文件时，操作系统底层其实经历了**两个截然不同的阶段**：

1. **阶段一：等待数据就绪**。比如网卡还没收到远端发来的数据包，或者磁盘磁头还在寻道。此时内核在等数据。
2. **阶段二：将数据从内核拷贝到用户空间**。数据到了内核缓冲区后，CPU 需要把它搬运到你 C++ 代码里的 `char buffer[1024]` 中。

**面试防坑指南**：所有的 I/O 模型分类（阻塞/非阻塞、同步/异步），都是在讨论操作系统在这**两个阶段**里的不同行为。

## 阻塞I/O

**技术对应**：线程调用 `read()`，发现没数据，线程立刻被操作系统**挂起（休眠）**。等数据来了且拷贝完了，线程才被唤醒。

**优缺点**：最简单，但并发极差。一个线程只能服务一个连接。

## 非阻塞I/O

**技术对应**：把 Socket 设置为 `O_NONBLOCK`。调用 `read()` 时，如果没数据，内核直接返回一个 `EWOULDBLOCK` 错误，**线程不休眠**。线程通常会写一个 `while` 循环疯狂询问。

**优缺点**：线程没被挂起，但疯狂的 `while` 轮询会**榨干 CPU 资源**。

## I/O多路复用

**多路**：指的是成千上万个网络连接（Socket / File Descriptor, FD）。

**复用**：指的是只用**一个线程**（或极少的线程）来统一管理和监听这成千上万个连接。

如果没有多路复用，如果有 1 万个玩家连入，服务器就得开 1 万个线程去阻塞等待，这会直接把操作系统的内存和上下文切换开销撑爆。

Linux 系统历史上给出了三代演进方案：`select` $\rightarrow$ `poll` $\rightarrow$ `epoll`。

### select

1. 你把想监听的 Socket 放进一个叫 `fd_set` 的集合里。
2. 调用 `select()` 时，把你手里的 `fd_set` **整体拷贝**到系统内核里。
3. 内核开始**死循环遍历**（轮询）这批 Socket，看哪个有数据了。
4. 发现有数据后，内核把修改过的 `fd_set` **再整体拷贝**回用户态。
5. 你的 C++ 代码拿到返回后，还得自己写个 `for` 循环，**再次遍历**一边 `fd_set`，找出到底是哪个 Socket 就绪了。

### poll

随着互联网发展，1024 个连接根本不够用。于是 `poll` 诞生了。

- **工作原理**：底层和 `select` 几乎一模一样，唯一的区别是：它把 `fd_set` 从“固定大小的 Bitmap” 换成了“**动态分配的链表/数组**”。
- **进步**：**突破了 1024 的连接数限制**，你想传多少传多少。
- **缺陷**：根本问题依然没解决！依然需要全量的内存拷贝，依然是 $O(N)$ 的低效遍历。连接数越多，性能跌得越惨。

### epoll

为了彻底解决 $O(N)$ 遍历和全量拷贝的问题，Linux 2.6 内核推出了 **`epoll`**，它是现代高并发服务器（如 Nginx、Redis）的绝对基石。

基于**红黑树**存储 FD，基于**回调机制**维护就绪链表。$O(1)$ 获取就绪事件，支持高效的 **ET 边缘触发模式**。

`epoll` 把原本 `select` 的一步操作，极其优雅地拆分成了三个函数：

1. **`epoll_create`**：在内核中创建一个 `epoll` 对象。
2. **`epoll_ctl`**：向 `epoll` 对象中添加、修改或删除你想监听的 Socket。
3. **`epoll_wait`**：死等，直到有 Socket 就绪，直接返回**那些已经就绪的 Socket 列表**。

#### **epoll更快**

**底层数据结构：红黑树**

内核用一棵红黑树来存储所有被监听的 FD。通过 `epoll_ctl` 添加或删除 FD 时，时间复杂度是 $O(\log N)$，极快，且不需要每次都把所有 FD 传给内核（解决了全量拷贝问题）。

**事件驱动：就绪链表 + 回调机制**

这是 `epoll` 的灵魂！当网卡收到数据时，硬件会触发中断，内核会通过**回调函数**，把那个来数据的 Socket **主动放入一个双向链表（就绪链表）中**。

**$O(1)$ 的获取机制**

当你调用 `epoll_wait` 时，内核**根本不去遍历红黑树**，而是直接去看“就绪链表”里有没有东西。有的话，就把这几个就绪的事件拷贝到用户态给你。

> **对比**：10 万个连接里有 2 个发了消息，`select` 检查 10 万次，`epoll` 检查链表，直接把这 2 个交给你。

**I/O 多路复用（epoll）是同步还是异步？**

**标准答案：是同步 I/O。**

- **判定标准**：谁负责完成**阶段二（把数据从内核搬到用户态）**？
- 如果需要**你的线程自己**去调用 `read()` 把数据搬过来，那它就是**同步 I/O**。BIO、NIO、I/O 多路复用，全都是同步的！在 epoll 里，操作系统只是通知socket数据到了。
- 只有当**内核自动帮你把数据搬到了 buffer 里**，才叫**异步 I/O**。

#### epoll水平触发

**水平触发：默认模式（保底安全）**。

- **逻辑**：“不断提醒”。只要 Socket 的缓冲区里还有数据没读完，每次调用 `epoll_wait`，内核都会通知你：“嘿，有数据，快来读！”
- **特点**：编程简单，不容易漏读数据。

#### epoll边缘触发

**边缘触发：高性能模式**。

**逻辑**：“只提醒一次”。只有当 Socket 的状态**发生变化**（比如新来了一批数据）的那一瞬间，内核才通知你一次。如果你没把数据读完，下次 `epoll_wait` **绝对不会**再通知你了。

**特点**：减少了 `epoll_wait` 的系统调用次数，性能极高。

**硬性要求**：在 ET 模式下，你必须把 Socket 设为**非阻塞 (Non-blocking)**，并且写一个 `while` 循环不断去 `read`，直到返回 `EAGAIN`（缓冲区彻底读空了）为止。

## 同步/异步io

**同步**：内核说“数据准备好了”，但**你必须亲自（你的线程）**调用 `read()` 去把数据从内核态拷贝到用户态。在拷贝的这短暂时间里，你的线程是被卡住的。

**异步**：你发起请求后就什么都不管了。内核不仅负责等待数据，还负责**亲自把数据拷贝到你指定的 Buffer 里**。全部搞定后，内核给你发个信号或者触发一个回调函数。

组合有四种：

- 同步阻塞
- 同步非阻塞
- 同步+I/O多路复用
- 异步I/O
