# 输入URL到页面展示发生了什么

## 输入URL并解析

**URL 解析：** 浏览器首先会解析输入的 URL，识别出协议（如 HTTPS）、域名、端口（默认 80 或 443）、路径和参数等信息。

**检查缓存：** 在真正发起网络请求前，浏览器会先检查本地缓存（强缓存）。如果发现请求的资源在缓存中且未过期，浏览器会直接加载缓存内容，不产生网络请求。如果需要验证（协商缓存），则会进入后续流程。

## DNS域名解析

**浏览器缓存：** 浏览器自身记录的 DNS 缓存。

**操作系统缓存：** 查询本地系统的 hosts 文件。

**路由器缓存：** 家用路由器上的 DNS 缓存。

**ISP DNS 服务器：** 本地运营商（如电信、联通）的 DNS 服务器。

**递归与迭代查询：** 如果以上都没有，ISP DNS 会向上级（根域名服务器 -> 顶级域名服务器 -> 权威域名服务器）发起查询，最终拿到目标 IP 地址并返回给浏览器。

## 建立TCP连接

得到 IP 地址后，浏览器会通过操作系统调用，与服务器建立可靠的 TCP 连接。这个过程就是经典的**三次握手**：

1. 客户端发送 `SYN`（同步）报文，询问服务器是否可以建立连接。
2. 服务端收到后，返回 `SYN + ACK`（同步+确认）报文，表示同意建立连接。
3. 客户端再次发送 `ACK`（确认）报文，连接正式建立。

## TLS/SSL握手

如果使用的是 HTTPS 协议，在 TCP 连接建立之后，还需要进行 TLS/SSL 握手来建立安全通道。

- 这个过程主要是客户端和服务器交换证书，验证身份，并协商出一个**对称加密的会话密钥**，用于后续所有传输数据的加密。

## 发生HTTP/HTTPS到服务器

连接和安全通道建立完毕后，浏览器会构建并发送 HTTP 请求报文。

- 报文包含：**请求行**（Method, URI, HTTP Version）、**请求头**（如 User-Agent, Cookie, Accept 等）和**请求体**（POST/PUT 才有）。

## 服务器处理HTTP请求并返回报文

服务器（如 Nginx, Tomcat）接收到请求后，根据路由分发给对应的后端程序。

后端程序处理业务逻辑（如查询数据库、读取文件等）。

处理完成后，服务器生成 HTTP 响应报文返回给浏览器。响应包含：**状态码**（如 200 成功，301/302 重定向，404 找不到，500 服务器错误）、**响应头**和**响应体**（HTML 文档、JSON 数据等）。

## 渲染浏览器页面

1. **解析 HTML：** 构建 **DOM 树**（Document Object Model）。
2. **解析 CSS：** 构建 **CSSOM 树**（CSS Object Model）。
3. **合并渲染树：** 将 DOM 树和 CSSOM 树结合，生成 **Render Tree**（渲染树），剔除不可见的元素（如 `display: none`）。
4. **布局 (Layout/Reflow)：** 也叫**回流**，计算渲染树中每个节点在屏幕上的确切几何位置和大小。
5. **绘制 (Paint/Repaint)：** 也叫**重绘**，遍历渲染树，调用系统的绘画 API 将每个节点真正的像素绘制到屏幕上。
6. **合成 (Composite)：** 处理层级关系和复杂的动画效果，最终呈现给用户。

## 断开连接四次挥手

在现代 HTTP/1.1 及更高版本中，默认开启了 `Connection: keep-alive`，TCP 连接会被保持一段时间以供后续请求复用。但当满足断开条件时，双方会通过**四次挥手**来安全地断开 TCP 连接。

# 函数调用发生了什么

函数调用≈一次控制流跳转+栈帧构建

```c++
C++调用
   ↓
编译器 → call指令
   ↓
CPU执行：
   1. 压返回地址
   2. 跳转函数
   ↓
建立栈帧
   ↓
执行函数体
   ↓
ret
   ↓
恢复现场
   ↓
继续执行
```

## 用户态：栈帧的更替

**参数传递**

- 调用者（Caller）会根据特定的**调用约定准备参数。
- 通常前几个参数（如前 6 个）会直接放入 CPU 寄存器（如 `rdi`, `rsi`, `rdx` 等）中以提高速度，多出来的参数才会按照从右向左的顺序压入栈（Stack）中。

**保存返回地址**

- CPU 执行 `call` 指令。这个指令会自动将**下一条指令的内存地址**（即当前指令寄存器 `rip/eip` 的值）压入栈中。这是为了确保被调用的函数执行完后，程序知道该回到哪里继续执行。

**函数序言—— 建立新栈帧**

- 进入被调用函数（Callee）后，首先要做的就是保存现场并开辟自己的地盘。
- 通常包含两条核心汇编指令：
  - 先保存旧的栈底指针（`push rbp`），然后将当前栈顶作为新栈帧的栈底（`mov rbp, rsp`）。
  - 接着，通过减小栈顶指针（`sub rsp, X`）来为该函数内部的局部变量分配内存空间。
- *(很多内存泄漏检测工具或像 Frida 这样的动态 Hook 技术，做 Inline Hook 时，本质上就是篡改这段“函数序言”的汇编指令，让程序跳转到我们自定义的逻辑里。)*

**执行函数主体**

- 利用分配好的栈空间和寄存器执行实际的逻辑代码。如果函数有返回值，通常最终会存放在 `rax`（或 `eax`）寄存器中。

**函数返回**：弹出返回地址、跳回调用点

- 函数执行完毕，需要“打扫战场”。
- 通过 `leave` 指令（相当于 `mov rsp, rbp; pop rbp`）销毁当前栈帧，恢复调用者的栈底指针。
- 最后执行 `ret` 指令，CPU 会将栈顶存放的那个“返回地址”弹回到指令寄存器（`rip`）中，控制权完美交还给调用者。

## 系统调用：操作系统层面

如果你的函数调用涉及到操作系统的核心资源，比如读写文件（`read/write`）、分配大块内存（触发了 `mmap` 或 `sbrk`）、或者创建线程/网络通信等，普通的栈帧操作就不够了，必须**陷入（Trap）操作系统内核**。

**准备系统调用号：**

- 标准库（如 glibc）会将对应的系统调用号（例如 `sys_read` 对应的数字）放入 `rax` 寄存器中，并将相关参数放入其他寄存器。

**触发陷阱 (Trap) 与态的切换：**

- 用户程序不能直接跳到内核代码。它必须执行一条特殊的指令（如较老的 `int 0x80` 软中断，或现代 x86-64 架构下更高效的 `syscall` 指令）。
- 这条指令会触发一个异常，导致 CPU 的特权级从 **Ring 3（用户态）瞬间切换到 Ring 0（内核态）**。这个切换是非常昂贵的，涉及硬件级别的权限变更。

**上下文切换与保存：**

- 进入内核态后，操作系统接管了控制权。它首先会将当前用户进程的上下文（所有的通用寄存器状态）保存到该进程专用的**内核栈**中，防止数据被破坏。

**查表与执行：**

- 内核会根据 `rax` 里的系统调用号，去查找**系统调用表**，找到对应的内核处理函数地址并开始执行真正的底层硬件或内核逻辑。

**恢复现场与返回：**

- 内核逻辑执行完毕后，将结果返回码放入 `rax`。
- 操作系统从内核栈中恢复之前保存的用户进程寄存器状态。
- 最后，执行特殊的返回指令（如 `sysret` 或 `iret`），将 CPU 特权级从 Ring 0 降回 Ring 3，程序继续在用户态愉快地跑下去。
